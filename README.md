# LaFix

**修复 ColorOS 16 上第三方桌面启动器的兼容性问题，让返回桌面、最近任务与系统导航恢复正常。**

LaFix 是一个基于 [libxposed](https://github.com/libxposed) API 102 开发的运行时修复模块，面向 ColorOS 16（Android 16）系统桌面在第三方 Launcher 作为默认 Home 时出现的一系列兼容性问题。

## 问题背景

在 ColorOS 16 中，系统桌面（`com.android.launcher`）承担的不仅是桌面显示，还深度参与了 Android 系统的 Home 切换、最近任务管理、窗口转场和导航事件处理。

但 ColorOS 对这些功能的部分实现存在一个隐含前提：**系统桌面必须是当前默认 Home。**

当用户将 Nova Launcher、Niagara Launcher 等第三方桌面设置为默认启动器后，系统桌面内部的一些逻辑仍然按照默认桌面场景运行，却无法正确完成对应的动画收尾、图层状态更新和输入事件派发。

由此引发一系列相互关联的问题：

- **返回桌面出现壁纸空窗**：按 Home 或通过手势返回桌面时，屏幕先显示纯壁纸，等待一段时间后桌面图标和小组件才突然出现。
- **返回桌面后短暂失去响应**：按下 Home 后约 0.9 秒内，导航栏的返回键、任务键以及桌面上的图标可能无法正常响应点击。
- **最近任务键短暂失灵**：Home 操作后约 0.25 秒内再次按下任务键，事件可能被系统内部的按键守卫直接丢弃。
- **桌面意外参与应用退出动画**：从 LSPosed 管理器等半透明 Activity 返回时，底层桌面可能被错误识别为退出中的应用，跟随前台应用一起缩小、淡出。
- **最近任务启动异常**：任务键可能进入不合适的冷启动 Activity 路径，导致响应延迟、白帧甚至偶发崩溃。
- **连续调用最近任务失败**：短时间内重复打开最近任务时，系统内部的任务启动限制可能错误拒绝后续请求。

这些问题并非第三方桌面本身的实现缺陷，而是 ColorOS 系统桌面在非默认 Home 场景下存在的逻辑兼容性问题。

## 修复内容

| 问题表现 | 内部原因 | LaFix 修复方案 |
| --- | --- | --- |
| 返回桌面只显示壁纸 | Fallback Home 图层只更新了 matrix / alpha，遗漏可见性状态更新 | 在同一笔 SurfaceControl 事务中补充 `setShow()` |
| 桌面跟随应用缩小淡出 | 返回动画错误地将 `activityType=HOME` 的桌面图层识别为退出应用 | 仅在 `SWIPE_TO_HOME` 且第三方桌面为默认 Home 时修正动画目标判定 |
| Home 后约 0.9 秒无法操作 | Home 按键触发模拟退出动画，内部运行 Recents 动画并接管触摸及导航输入 | 直接派发 Home Intent，跳过不必要的模拟退出动画 |
| Home 后约 0.25 秒任务键失灵 | Home 键与菜单键同击保护逻辑吞掉紧随其后的任务键事件 | 第三方桌面场景下取消该拦截逻辑 |
| 最近任务启动缓慢、偶发白帧 | 最近任务启动退化为独立 Activity 冷启动路径 | 恢复命令队列派发路径 |
| 最近任务偶发崩溃 | `getRecentsView()` 将 `RecentsActivity` 无条件强制转换为 `Launcher` | 改为安全类型判断，无法获取时回退到冷启动路径 |
| 连续按任务键没有响应 | 同一任务在距上次启动不足 1 秒时被拒绝 | 第三方桌面场景下放宽重复启动时间限制 |

## 支持环境

| 项目 | 已验证环境 |
| --- | --- |
| 操作系统 | ColorOS 16 |
| Android 版本 | Android 16 |
| 系统桌面包名 | `com.android.launcher` |
| 系统桌面版本 | 16.4.5 |
| Version Code | `160040005` |
| Xposed 框架 | LSPosed 2.2.0 |
| API 兼容性 | libxposed API 101 / 102 |
| 导航方式 | 三键导航、手势导航 |

**兼容性说明**

以上为目前实际完成验证的环境，不代表所有 ColorOS 版本、系统桌面版本及第三方启动器均已得到验证。

LaFix 使用反射定位系统桌面内部 API。当系统升级导致目标类、方法或字段发生变化时，对应 Hook 将记录 `unsupported` 并自动跳过，不会因为单个 Hook 不兼容而主动导致系统桌面崩溃。

其他仍然匹配的修复逻辑可以继续独立运行。
